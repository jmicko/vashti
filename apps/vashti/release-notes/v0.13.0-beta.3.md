# v0.13.0-beta.3

This beta refines image workflows and integrates the tested Kuno image residency
and Intel performance updates. Update Vashti, Android, and Kuno together. Stable
installations remain on v0.12.0.

## Images

* Added encrypted, account-scoped device-only image flows and gallery storage.
  Kuno still handles inference transiently; private results are not saved on the
  Vashti server.
* Fixed native image downloads to export authenticated image bytes through the
  Android save interface rather than a browser-only download link.
* Allowed image edits with an empty prompt, including aspect-ratio changes.
* Preserved prompts after generation and original-image edits; accepted iterative
  edits clear only the submitted prompt, not newer text typed during generation.
* Added bounded image caching, shared decoding, stable image dimensions, and
  nearby-image preloading to reduce loading jumps when scrolling and reopening.
* Reorganized the gallery into compact photo tiles with selectable image stacks.
* Collapsed the mobile composer when unfocused and added gallery attachments
  without navigating away from the image flow.
* Added full-size reference viewing while composing, with navigation between
  multiple references and focus restoration when the viewer closes.
* Added a hold-to-compare control for edited results in flows and the gallery.
  It shows the first reference actually submitted for that edit, including the
  previous output for iterative edits, without changing the displayed frame.

## Kuno

* Retained model-only image residency between requests while clearing request
  prompts, references, outputs, and previews. Cancellation and uncertain cleanup
  discard the worker instead of reusing private request state.
* Added the ABI 2 managed Intel runtime and selected whole-RoPE/residual execution.
  Controlled local B70 checks measured warm generation about 20% faster and
  editing about 15% faster than the previous resident runtime.
* Revalidated the shared native engine on CUDA and Vulkan math fixtures, with
  original-resolution CUDA generation/edit transport and lifecycle checks.

## Optional Intel Runtime

The runtime is a separate, explicit installation; upgrading the ordinary Kuno
package preserves an existing runtime but does not replace or enable it.
Download [kuno-sycl-linux-x86_64.tar.gz](https://vashti.chat/releases/v0.13.0-beta.3/kuno-sycl-linux-x86_64.tar.gz)
and verify its SHA-256 before extracting into a new, empty directory:

```sh
printf '%s  %s\n' \
  85d7aecb92e9e27af85f56bf5569d31feffd63d37955e7549ac081ab3e3e54a3 \
  kuno-sycl-linux-x86_64.tar.gz | sha256sum -c -
mkdir kuno-sycl-runtime-beta3
tar -xzf kuno-sycl-linux-x86_64.tar.gz -C kuno-sycl-runtime-beta3
sudo kuno install-image-runtime \
  --directory "$(pwd)/kuno-sycl-runtime-beta3" \
  --manifest-sha256 fc169dd2bf4418c2770940c85ec570f5b0a8c5ddaa21e32176cf839b36c88baa
```

To enable Intel execution, configure the existing image settings with
`engine: "managed_sycl"`, `runtime: "qwen21-sycl-2026.1-v1"`, the model store and
collections, and the intended GPU PCI address. Apply them using
`sudo kuno configure-image --settings /absolute/image-settings.json`.
Both operations ask before interrupting inference. The gateway also accepts
older installed ABI 1 bundles, but those do not gain model-only residency.

## Beta Limits

The Intel runtime was tested on Arc Pro B70 with working Xe/Level Zero drivers
and GLIBC 2.39. Its CPU objects require AVX2, F16C, FMA, and BMI2. Standard
attention is the only advertised Intel mode. Other hardware and indefinite
stability remain unverified.

The standard CUDA/Vulkan Kuno archive requires `libcuda.so.1` and Vulkan/GNU
runtime libraries, even on an Intel-only host. It does not need the development
toolkit, but it is not a driver-free or general CPU-only build.

Browser and automated image-flow checks do not establish physical Android
export/gesture acceptance. Full live Vulkan image acceptance, matched ComfyUI
performance, and pixel-level quality equivalence are not claimed.
