# Fixed-public numeric boundary source checkpoint

The original source-only candidate is now integrated and selected only by the
protected named laboratory mode `resident-numeric-boundaries-probe`. Both-card
position0/count1 device/audit evidence is recorded in
[the device receipt](../text/receipts/rust-native-numeric-boundaries-device-20261006.json);
the latest root state is in [the checkpoint](../../../../docs/kuno-native-text-checkpoint.md).
No production route,
whole-model bitwise acceptance or arithmetic change is implied. The typed entry is
`resident_model::numeric_boundaries::run(file, lifecycle_probe::RunConfig)`.
The caller must supply the actual once-configured transient client, limits,
vendor and retirement Arc. The protected CLI supplies these after checking owned
transient I/O and full-audit prerequisites before device creation. Ordinary
collectors are unarmed and perform no client, map, audit or admission action.

The fixture binds the unchanged original Qwen graph and the existing fixed
public `!` tokenizer input. It runs four fresh pairs, each serialized on the
same physical client. A scalar complete step and a native complete count1
chunk both use position0 and normal full-model acceptance. Each pair captures
exactly one boundary:

| Static boundary | Active values | Scalar full map | Native full map |
| --- | ---: | ---: | ---: |
| layer0_combined_ple_input | 10,240 | 65,536 B | 524,288 B |
| ple_projected_key | 10,240 | 65,536 B | 524,288 B |
| ple_projected_value | 2,560 | 32,768 B | 131,072 B |
| ple_injected_residual | 10,240 | 65,536 B | 524,288 B |

The original tensor metadata must prove KEY is 10,240 rows by 2,560 columns
and VALUE is 2,560 rows by 2,560 columns. Residual channels are independently
proved as four streams by 2,560. All handle epochs/layouts, full actual physical
extents, same stream/client and distinct fault/stage owners are checked before
mapping. Active values must be finite. Every inactive token and padding word
must be zero; a short owning read cannot be accepted.

There are no additional MAIN pages: each scalar owner retains the original
1,286 pages / 785,186,816 B and each native owner retains the existing
1,376 pages / 818,249,728 B. No committed state/cursor import, mathematics,
kernel schedule or numeric tolerance is changed. Armed diagnostic maps add
completed inference dependencies at the selected boundary only.

Each snapshot is guarded before reserve, allocates exactly 10,240 u32 words,
initializes its full actual capacity, and never grows. Two retained snapshots
cost 81,920 B. The full stage map costs at most 524,288 B; the earlier 32,768 B
fault map drops before the stage map. A separate 4,096 B metadata reservation
gives a diagnostic guarded-host bound of **610,304 B**, below 1 MiB. The
original application bound 11,075,584 B plus this reservation is 11,685,888 B,
below the unchanged 12 MiB application bound. Normal guarded vocabulary
results are immediately dropped and use the original model host inventory.

Runtime keeps the original independent hard **67,108,864 B** cap. Fault and
stage readback spans plus their audited duplicate headroom reserve
`2 * (32,768 + 524,288) = 1,114,112 B`. The metadata-only original Plan runtime
bound is read and checked before private allocation/fill. Original worst F32
head 64,090,112 B plus the extra reservation is **65,204,224 B**, leaving
1,904,640 B; original Q6 head 64,000,000 B plus the extra reservation is
65,114,112 B. No runtime credit, raised limit or fallback is invented.

The full fault read and then full stage read complete under the actual
admission callback. Both guarded Bytes leases scrub/drop before audited I/O
sanitation, receipt validation and the normal forced admission checkpoint.
No ledger callback reenters admission. Polling for ordinary inference remains
unchanged; bounded sanitation starts only after the completed maps. Unexpected
map/format/audit/panic/cancellation failure poisons the sequence and retires
the actual context. An incomplete capture cannot be taken.

After capture, every scalar/native operation still completes its ordinary
whole-model fault, lease, PLE history, all-family preflight and acceptance path.
The reused actual lifecycle owner explicitly closes and verifies the full
model and executor before returning either snapshot. Both owners in a pair
have closed and dropped before exact bit mismatch/max-absolute comparison.
All eight owners must close before a receipt is returned. No vector, token ID,
route ID, content hash or private value appears in errors or reports.

The receipt remains diagnostic and sets whole-model numeric and performance
acceptance false. This count1/position0 fixture can locate a divergence across
these four boundaries; it cannot locate an earlier layer0 substage, prove
later chunk/state equality or attribute the existing count4/count8 logit
deltas by itself. The separately documented native PLE GPU f32 tail and
original scalar CPU f64 tail remain different topologies.

Source checkpoint checks: five focused host tests cover exact one-shot
packets, full owning extents/inactive/padding/finiteness, raw lease ordering,
fault/audit failure, full-capacity wipe on unwind, bitwise comparison and
checked aggregate budgets. Strict all-target Clippy and formatting cover the
actual connected source. Those host checks alone establish no GPU execution,
physical cleanup or numeric acceptance. The parent subsequently registered the
protected CLI and completed both-card execution, owning cleanup and receipt
validation as linked above; whole-model bitwise acceptance remains false.
