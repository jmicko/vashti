Alright, so I basically want two flows. A tool that models can use in chats just like all the other tools, and a dedicated image generation section of the app that relies less on llms but can utilize them.

I think the tool version is pretty self-explanatory. Probably a group of tools for image generation, namely a generate tool, and an edit tool. Obviously the generate tool will generate an image from scratch, and the edit tool will edit an image or group of images. The tools should work like the qwen 2.1 workflows we've just been working on. The user should get settings to control the default params like steps, resolution, cfg, etc. There should also be an option for the models to put in whatever params it wants to. I think in this mode, perhaps, that the model should be able to see the defaults, but change them as it sees fit. Maybe one of the options for settings should also be to let the model decide. So like you might want to have 50 steps no matter what, but you want the model to decide the aspect ratio. You would maybe pick a default, but then check a box to say model can change. Then the model can change it, or just let it go with the default. This mode would be a more agentic flow, where the model would generally be making the prompting decisions and whatever. You might say "generate a weasel" and it would expand that prompt into something that will generate a proper weasel image. Then in the same thread after you get the weasel image, you might say "make it a white weasel". At this point, the model could regenerate with a different prompt, or it could send the image into the edit tool and just tell it to change the weasel to white. We basically give the model a full suite of tools to use as it sees fit to fulfil the needs of the user.

The dedicated image section should basically be a sub-app living inside vashti, just like the notes app. We put a button under the new chat but above the notes button for it. You go there and you get a navigation choice to see your gallery, generate images, or edit images. Generating images will be something like a conversational flow. You'll have your positive and negative prompts, then a bunch of other settings under it like cfg, steps, aspect ratio, etc. Maybe a way to show or hide each setting, including the negative prompt. So if you did that you would have what looks basically like our normal conversation view. You type a prompt, hit send, and the response is an image. Hit send again and get another image. If you've got the seed set to change automatically, you would obviously get different images with the same prompt. You should also be able to select how many images to generate, and it will keep going until you hit that number. Obviously when generating, the send button should change to a stop button and will stop all generation. We should also have an endless option where it will just continue generating. If you don't have random/incremental seed turned on, it should warn about that before it lets you do it lest you get flooded with a billion of the same image. Images in the chat should have some tools attached to them. So like if you make an image that you really like but want to tweak it, you could hit the edit tool and bring it into the image edit flow to make your changes.

The edit flow is maybe a little trickier. I think we need to distinguish between iterative editing and just changing the prompt. With iterative editing, you would take an image, say the cabbage man we've been using. You might say "change the cabbages to carrots" and it would do that. Then you might say "make his shirt blue". It would take the newest carrot image, and make the shirt blue. You would have a man in a blue shirt with carrots, even though the recent prompt only said to change the shirt to blue. You are iterating.

Then of course there's the non-iterative mode where you have the image you want to edit, and you enter a prompt. You get your image back, and change the prompt based on those results. So if you first said to change the cabbages to carrots, and then you wanted his shirt to also be blue, you would have to change the prompt to "change the cabbages to carrots and change his shirt to blue" in order to get both changes done. This is because in non-iterative mode it is always using the original image as the base.

I think in iterative mode, there should be a retry button under each image. That's how you get it to try again with a different seed, just like when we regenerate messages in a conversation. We do the same with images and you can slide between them to pick the one that you want to continue the iterations with.

In the gallery mode, I think by default we should have the retried generations be stacked, with the top of the stack being whichever image is focused in the workflow. when you tap into one of these images for the full screen view, you should be able to slide through the other iterations, and should also be able to copy one out of the stack so you see it in the gallery view.

To specify, in regular llm chats, if the model uses the image tool, and then you regen that message, I would say we don't stack any images that come out of those retries. 

In iterative mode, you should also be able to back up and edit a prompt so that if you decide against an edit, you can go back to before it was made. Our tree architecture from conversation mode might actually be usefull for image gen flows now that I'm thinking about it, and I think we should consider using it here too.

One of the things I hate the most about comfyui is how hard it is to move around on mobile. Going from prompt editing to seeing the resulting images is difficult because you risk moving nodes around. Moving nodes around is create for creating the flow, but I spend most of the time just changing prompts and a couple of settings. For our app, I think just scrolling up and down is all we need. You send your prompt, and the image should show up above the input for the prompt and all your settings. You can scroll down to see all your settings, and scroll up to see the images that have been generated. Images on mobile should be nearly the width of the screen. On desktop they should just be a reasonable size since desktops can be pretty wide. Maybe limited by width and height of the viewport. Don't want it to be too tall, don't want it to be too wide. In regular chat mode, we should just handle images the way we already do. But in image gen/edit modes, we are more focused on the images so they should be as big as is reasonable.
