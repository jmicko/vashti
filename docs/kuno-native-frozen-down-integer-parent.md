# Immutable frozen integer-DOWN parent contract

This internal source candidate uses the alternate arithmetic in
[kuno-native-frozen-down-integer-eight.md](kuno-native-frozen-down-integer-eight.md).
It is default-off and has no physical numerical or speed acceptance from
source tests. Every original CPU13 vector, carry, greedy and real-repair
comparison keeps its original tolerance. Full target-greedy verification is
unchanged. No profile, expert-slot count, cap or safety-margin fallback is
permitted.

The eventual public selector is
`KUNO_LAB_FROZEN_DOWN_MATH=integer-public`. The controller must validate the
original fused full-Q8 speculative MTP before any model allocation. Intel is
the current physical placement trial; any retained legacy Nvidia parser
composition requires the same scope and separate numerical acceptance. Target-only, English-pruned and subgroup-broadcast draft variants
are outside this first candidate. The target parent has no MTP reference and
does not claim to authenticate that separate workspace; it authenticates the
actual target permissions, sources, routes and owners described below.

`Config::reserve_public_frozen_down_integer()` reserves an independent private
owner and its complete transient allowances before target allocation. It
requires target rows/checkpoint, exactly one original public request-I/O
permission, frozen host sources and their GPU router, MAX8/tile8, and no CPU
hybrid, resident router, prepared experts, live-member reduction or packed HOST
staging. `executor.target_frozen_down_integer_reserved` must equal this real
Config permission; its default and both existing reset paths are false.
Construction validates the leaf's device limits before any new owner allocation.

Old attachment methods forward `down_integer=false`. The new explicit
`ResidentModel::attach_public_host_sources_with_down_math` takes the same
existing source/schedule arguments plus `down_integer: bool` immediately
before cancellation. The prepared attachment and Sources factory apply the
same immutable bool and conflict checks. Permission, actual workspace owner
and executor marker must match exactly. Attachment follows the original
accepted public language prompt at the exact prompt cursor or one-shot CPU13
warm reset at position0 and source-bank freeze, before request I/O; the full graph/source hash, Mirror, epoch, same
client/stream, imported-page provenance and pending pin proofs remain required.

Selected DOWN requires original partition exit and the real frozen GPU router,
count1..3/full token wave starting at0, original deferred/transient chunk I/O,
fused Verify3 dense dispatch, target rows/carry and checkpoint. Competing
four-row DOWN, DOWN stride-four, shared-DOWN scales, private/workgroup tables,
GU factors, paired GU, staged sources and three-member MoE arithmetic reject
before source import. Original plain GU or separately admitted integer GU and
its stride-four scheduling compose. Grouped PLE/status, original QSA selection
and ThreeGdn compose independently. Selected source execution also rejects
Advance/LastLogits purposes and counts outside1..3. Old projection/count1
policy setters cannot replace the selected scope.

For each actual layer, the selected ordered source path is:

1. Enqueue all five original gate/up source partitions, retaining the original
   slots, dtype, private MAP rank and ACT/status addresses.
2. Enqueue exactly one leaf preparation of all30 original route positions from
   actual private ACT/status, after every gate/up consumer.
3. Enqueue the five corresponding original packed DOWN sources with the new
   leaf's eight-row/eight-lane geometry.
4. Enqueue the leaf's audit of every word of the complete scratch owner into the
   original full fault owner, then all original finite/fold/reduction checks.

The unselected source path retains its original five interleaved GU/DOWN pairs.
The source MAP, original router, rank probabilities, reduction/fold, target
head, both full completed fault proofs, PLE transitions and all-family commit
order remain unchanged. Preparation uses grid `(1,30,1)`/64, DOWN uses
`(320,groups,1)`/64 with the authenticated maximum30 envelope, and the complete
owner audit uses `(256,1,1)`/64. These are new mathematical DOWN calls, not
original-F32-equivalent operations.

The independent exact charges are:

| Increment | Bytes |
| --- | ---: |
| MAIN, one complete owned private root | 65,536 |
| HOST, complete owning read/closure allowance | 65,536 |
| Two INFO calls per layer,48 layers | 196,608 |
| Runtime including that INFO and bounded clear/read/close allowance | 462,848 |

Allocate `SCRATCH_WORDS=16384`, never an uncharged alias of GU or ACT. Meaningful
payload is `HEADER_WORDS +MAX_ROUTES*FRAME_WORDS =64+30*360 =10864`.
Headers0..29 are route readiness,30..63 and the owning tail are zero; inactive
route frames are zero. GU and DOWN integer permissions add their charges
independently. INFO is already included in runtime and is not counted twice.
Combined Intel admission must add the new MAIN+runtime while reserving HOST
separately, retaining its original complete-public-owner inventory and512MiB
margin. Complete-root layout/stream/buffer disjointness includes both integer
owners, all other target owners and every immutable original source page.
Startup, warm reset, full owning zero-close and device recovery include the new
page through the arena's original all-owner machinery; no owner is reused.

Only a successful prepare, all five successful leaf calls and the successful
full audit can create the private `DownIntegerDispatch` receipt for the exact
layer/count. The original pending source proof must also carry the real GPU
router owners. `Counters::add` validates it during the original accepted layer
commit. Public fields are `down_integer_preparations`,
`down_integer_dispatches`, `down_integer_audits`.
`native_frozen_source_down_integer(executor)` first requires a healthy complete
native boundary and full outer proof, then requires positive exact1:5:1 and
`source_dispatches=10*preparations`. Requests, attempts, partial calls, missing
shards, wrong layer/count, unselected calls and overflow earn no credit. Failed
or partial all-family publication remains poisoned and cannot produce a usable
completed getter. Original warm count1 therefore joins48:240:48 and480 original
source calls; larger receipts join all actual accepted chunks/repairs.

Focused source tests check all48 real mixed DASLab geometries, exclusive source
policies, exact default/selected phase ordering, strict actual receipt joins,
independent GU/DOWN owner and runtime charges, and constructor exact-private
extent rejection. Leaf shader/arithmetic checks and parent CPU checks are
separate from mandatory original physical gates and matched generation timing.

and two CPU jobs passes all 13 focused integer-DOWN tests (seven leaf and six
