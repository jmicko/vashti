# Fixed-public profile-ranked bank filler controllers

This is a separate default-off compiled-public placement experiment based on
`77e421c`. Read the [leaf/parent contract](kuno-native-public-profile-ranked-bank-filler.md)
for the pinned public profile, MIT notice, original completed-boundary and
publication proofs. The leaf and controller are separately owned. Source
selection, physical numerical acceptance and measured speed are separate gates.

## Selector and scope

The sole canonical selector is
`KUNO_LAB_FROZEN_BANK_FILL=profile-ranked-public`. It selects the typed
`PublicHostBankFillPolicy::StrataRankedFiller`. Absence selects `Original` and
preserves all existing controller scopes and setup behavior. Unknown values,
duplicates, arbitrary profile paths or hashes, and inherited experiment keys
are rejected before model allocation. There is no profile download, runtime
path, private profile or fallback selector.

Initially, selection requires the original public Intel target and independent
Intel full-Q8 speculative MTP: fixed 200-token code/prose fixtures or single warm CPU13 replay,
frozen HOST sources, actual GPU router, partition exit, direct original packed
fill, inline Verify3 fused projections, chunk I/O, request reuse and fused MTP
sweeps. Shared Q8 head is allowed. No target-only, Nvidia, Q2, English vocabulary,
broadcast head, prepared experts, live reduction, private/workgroup tables,
shared DOWN scales, GU factors, two-row GU, packed staging or three-member math
is admitted by the new selector. The old `preserve-public` bank-placement flag
cannot combine with it.

GU integer/stride, original four-row DOWN/stride or integer DOWN, grouped PLE,
grouped status, chronological QSA, bounded three-GDN, packed IQ4 and finite
submission backlog compose under their original independent guards. The new
selector does not relax an existing policy's exclusions. Each physical label
still needs its original numerical and lifecycle gates; parser composition is
not physical acceptance.

## Actual setup boundaries

Language completes the original real prompt prefill first, with no selected
bank filler. Only after its accepted boundary and ended output leases does it
call `prepare_public_host_sources_with_fill_policy`. Every actual prefill
resident remains in its old slot, and only empty slots receive original weights
chosen from the fixed public rank prefix. Setup and attachment stay outside
normal generation timing. The unchanged full 512-ID map and sorted 368-ID HOST
complement come from the actual PreparedPlan and attached Source.

CPU13 cold inference, reference vectors, carries, greedy IDs and real repairs
remain unchanged. After the full accepted cold13 pass and ended request reuse,
preparation occurs at real cursor13, **before** the existing warm reset. The
reset retains the completed banks; original attachment occurs at cursor0, and
the warm pass still performs its actual first token0 before the same reference
checks. The controller neither substitutes experts nor forces routes.

Keeping cold residents can make the selected warm CPU13 entirely VRAM. This
candidate records the actual HOST/VRAM route counts and allows zero HOST only
in its explicit selected scope (or the unchanged old preserve diagnostic).
The default canonical diagnostic still requires positive actual routes in both
tiers. Selected CPU13 cannot replace that authoritative HOST-path arithmetic
control or establish a new HOST math claim by itself.

## Exact content-free receipts

Outer `frozen_bank_fill_mode` is `original` or `profile-ranked-public`;
`frozen_bank_fill_requested` records the request. Actual per-pass/record
`frozen_bank_fill` and `initial_prefill_frozen_bank_fill` are read from the
native completed getter. Their companion `frozen_bank_fill_receipt` and
`initial_prefill_frozen_bank_fill_receipt` contain:

- `selected` and `actual_policy` from the actual typed publication;
- `completed_layers`, `filler_experts` and `preserved_residents`;
- `bank_completion_experts`, joined to the real original FillStats result;
- the fixed public `public_profile_sha256` and
  `selected_public_rank_table_bytes` (13,824 when selected);
- `completed_setup_only`, `route_history_persisted:false` and
  `new_gpu_owner_bytes:0`.

Selected receipts require actual 48-layer publication, exact
`filler_experts + preserved_residents == 6912`, and filler equality with the
actual setup result. Overflow, missing setup, policy mismatch and surplus or
partial counters fail. Zero filler is valid when all slots were already full.
Original evidence has zero publication counters and no selected setup/profile
credit. Actual real language prefill and CPU13 cold evidence must be Original;
selected CPU13 warm first-token evidence must already contain the published
filler. The language attachment receipt and warm first-token receipt are checked
unchanged at the completed inference boundary.

CPU13 selected placement is additionally named
`frozen_bank_placement:preserve-routed-profile-filler`, avoiding a false claim
that it used the canonical 0..143 diagnostic set. No route IDs, profile ranks,
prompt, output, token vectors or user content are serialized or persisted.

There are no new GPU owners, runtime bindings, arithmetic kernels, source
geometry, capacity, model slots, budget relaxations, inference deadlines, APIs
or installed defaults. The fixed public table is charged inside the existing
completion-plan allowance by the leaf. Existing combined Intel admission,
full owning closures and physical memory recovery remain mandatory.

## Validation boundary

tests (120 total, including nine new filler checks), plus strict locked
direct-device all-target Clippy with two build jobs, formatting and diff checks.
The accepted leaf dependencies are normative `192d662` and source `53e889a`;
their original profile/selection/source regressions remain independently owned.
Physical original CPU13, canonical HOST control, source/owner closure, recovery
and compiler-idle matched code/prose timing belong to root. No throughput gain
or 30 tokens/s acceptance is claimed by this source work.


Root completed both original CPU13 gates and one same-artifact code200 pair on
frozen e5f1689. Numerical, actual setup, full owner closing and physical recovery
pass; the selected profile shows no measured normal speed gain. See the linked
leaf contract's root physical comparison and v167_intel_profile_filler_physical.
The default remains Original; no API, installed service or frontend change.
