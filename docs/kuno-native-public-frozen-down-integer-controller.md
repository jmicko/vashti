# Fixed public integer DOWN controller

The new internal selector is `KUNO_LAB_FROZEN_DOWN_MATH=integer-public`.
The underlying source/owner contract is in
[the immutable parent specification](kuno-native-frozen-down-integer-parent.md)
and [integer DOWN arithmetic](kuno-native-frozen-down-integer-eight.md).
Absence preserves the original DOWN path. Only fixed CPU13 single warm replay
and compiled code/prose200 speculative fixtures may select it, with original
frozen host sources/GPU router/partition exit/direct fill/inline/Verify3-fused/
chunk I/O/request reuse and explicitly original fused full-Q8 MTP. Empty,
malformed, duplicate or incomplete choices reject before model construction.

Initial scope rejects target-only instead of inventing draft selectors. The
existing GUinteger target-only path is unchanged. Intel is the current physical
placement trial; the retained legacy Nvidia parser obeys the same full-Q8
restrictions but still requires separate numerical acceptance. Shared Q8 head,
integer GU/stride, grouped PLE/status, chronological QSA and bounded ThreeGdn may
compose independently. Original four-row/stride DOWN, shared DOWN scales,
English shortlist/broadcast Q8/Q2 draft, tables, GU factors, two-row GU, staging,
three-member arithmetic, prepared/live reductions and preserved bank placement
reject. Default and unrelated PLE/status/target-only behavior stays unchanged.

Controller proof of speculative/full-Q8 placement remains separate from the
target parent, which cannot authenticate an independent draft workspace. It
reserves `Config::reserve_public_frozen_down_integer()` and the matching executor
flag before target allocation. The source owner is attached with
`attach_public_host_sources_with_down_math` using the existing schedule arguments
plus the explicit DOWN boolean; old wrappers stay unchanged. Actual selection is
read from `native_frozen_source_down_integer`, never inferred from the request.
CPU13 original cold arithmetic remains unchanged; its warm first count1 token
after consumed reset uses the selected arithmetic while retaining its original
full-vector reference. Real language prompt prefill remains on the original
path, with false/zero initial DOWN evidence before source attachment.

Actual scalar receipts join accepted source execution at one preparation, five
DOWN dispatches and one full-owner audit per layer, plus exactly ten original
source partition dispatches. Selected preparations must be a positive multiple
of 48. CPU13's first warm token requires exactly 48/240/48 and 480 original source
dispatches. Unselected DOWN counts are zero; original source dispatches may still
occur. Missing/surplus counts, selection mismatch and overflow reject. No
prompts, outputs, tokens, vectors or routing history are persisted.

Each selected DOWN owner adds MAIN 65,536, HOST 65,536, INFO 196,608 and conservative
RUNTIME 462,848 bytes. INFO is included within RUNTIME; HOST is charged separately
to CPU memory. Intel combined admission adds the new exact MAIN extent and the
conservative extra RUNTIME reserve without double-counting INFO/HOST as VRAM.
The original 134,217,728-byte runtime reserve, full 144 banks, full-Q8 draft bounds,
512 MiB shared driver margin and fixed public host caps remain unchanged. Typed
admission checks the actual selected GU/DOWN booleans against exact MAIN bytes;
no widened generic allowance or implicit fallback is accepted.

DOWN alone closes MAIN 1,381/828,932,096; GU+DOWN closes MAIN 1,382/828,997,632. Original
GU-only and target-only closure helpers retain their previous exact extents.
At the historical physical total 34,242,297,856/used 50,688,000 query, GU+DOWN/full-Q8
reserves 34,167,361,536 and leaves 24,248,320 bytes beyond the unchanged margin. This
is admission arithmetic, not live GPU availability or physical acceptance.

The outer receipt records `frozen_down_math`, requested selection and all four
exact increments. Actual per-pass/record `frozen_down_integer` and its counters
are distinct. Initial prefill selection/counters are recorded separately. Intel
admission additionally records actual GU/DOWN policy booleans and exact DOWN
increments. Existing borrowed Vulkan logical-device identity, independent draft
runtime, owning close and all numerical references/tolerances are preserved.

The exact counter object is `frozen_down_integer_counters`, with scalar keys
`preparations`, `down_dispatches`, `full_owner_audits` and `source_dispatches`.
Its initial counterpart is `initial_prefill_frozen_down_integer_counters`,
paired with `initial_prefill_frozen_down_integer`. Requested selection is
`frozen_down_integer_requested`; the four outer increment fields are
`frozen_down_integer_extra_main_bytes`, `frozen_down_integer_extra_host_bytes`,
`frozen_down_integer_extra_info_bytes` and `frozen_down_integer_extra_runtime_bytes`.
