# Fixed-public resident GPU routing experiment

This is an internal source experiment, not a default inference path or a speed
claim. It is enabled only for the already guarded DASLab/Unsloth ideal replay,
after a fresh complete owner has preloaded the actual experts recorded by the
unchanged training trace. Training, demand loading and ordinary hybrid count1
continue to use the original completed CPU router packet.

## Exact authorization and transaction

The complete constructor reserves every additional private GPU owner, its
runtime upload/readback/inspection cost and bounded host metadata before
allocation. At the original completed native boundary, replay activation binds
an opaque authorization to the graph, original file, workspace/arena, bank
instances, complete bank handles and the actual expert-to-slot maps. Only the
original packed low-bit profiles, 48 layers, 512 experts, ten selected ranks,
144 resident slots, count1 and the explicit compiled fixture are admitted.
Adaptive/secondary banks, Q8 activation arithmetic, alternative MoE kernels,
fills, evictions and bank replacement are forbidden while active.

Each layer keeps the existing full owning mixed/router fold and original GPU
top10 implementation. The selected raw scores, lower-ID tie rule and chosen-ten
softmax arithmetic are unchanged. A checked GPU mapper looks up those actual
IDs in the immutable slot table and writes the original rank-preserving
MAP/PROB/owner headers. An absent expert, malformed rank, duplicate slot,
nonfinite probability or changed source/owner is a terminal fault; no forced
expert or fallback is permitted. Both original bank segments may execute;
their existing group/status predicates ignore inactive groups. The existing
F32 gate/down and original rank0..9 merge remain unchanged.

The layer's routing packet and the exact consumed MAP/PROB/OWNER logical wires
are copied to a separate bounded audit owner before the shared scratch is
reused. The frame also binds its layer and token start. No layer maps a result
to the CPU. At the existing whole-token completion boundary one owning readback
validates all 48 actual packets, consumed wires and tails, current top10 rules
and exact resident slots. Only then
are the original `count1::Proof`, staged plan and `Pending` completed from those
actual audited routes. Every plan must contain zero uploads and zero CPU ranks;
its slots must equal the immutable table used by the GPU. This deferred proof is
not a replacement for the dispatch authorization. An unresolved deferred
receipt cannot enter the original all-family acceptance or commit.

Original file/bank/full-handle checks, all GDN/QSA/PLE/GR and shared-owner
preflight, fault/cancellation/context checks, full CPU reference vectors, greedy
IDs, trace membership and whole-owning erasure remain required. Actual accepted
GPU counters advance only after the deferred proof is resolved. A failure
poisons and closes the complete owner through the existing lifecycle.

## Scope and limits

The first implementation retains 48 frames of 9,322 u32 words in a 2MiB owning
audit page: 8,192 original packet words, 804 MAP words, 80 probability words,
244 owner words and two identity words. A separate 128KiB owning slot-map page
holds 48*512 logical u32 entries; absent experts use u32::MAX. Both complete
pages, including zero padding, are separate roots disjoint from the original
model/scratch/CPU owners and original public banks. Every source/target/map/
inspection mirror is charged conservatively. This adds 2,228,224 main bytes
and 9,183,232 runtime bytes, including extra INFO/slab credit, without reclaiming
the old runtime plan. Only this explicit mode admits the rounded 128MiB runtime
ceiling; the ordinary path keeps its 64MiB ceiling.

The separately added 4MiB host reservation contains the simultaneous full 2MiB
owning readback lease, the complete decoded Vec48 audit (original mixed/router
values plus consumed headers), frozen table/bank pins and bounded scratch. The
vector reserves its exact capacity before any private entry is populated; it
never reallocates populated inline headers. Raw maps and decoded values are
destroyed through the original audited owner cleanup. The frozen authorization
checks actual expert-to-slot mapping and bank/source/physical handle identity,
while permitting the original all-hit plans to advance their recency/revision
counters. Policy setters, demand fills, scalar bank mutations and oracle
preloads cannot be used after activation.

The opt-in is KUNO_LAB_RESIDENT_GPU_ROUTER=1, and requires the already protected
ideal mode, mapped Intel144 banks, cap10/GPU10, GPU routing, shared/fast dense
kernels and original unfused F32 experts. Its exact compiled windows are
Unsloth prefix23 or DASLab prefix13/full32; Q4, ordinary demand mode, adaptive/
secondary banks and alternative expert/Q6-head arithmetic are rejected before
device creation. Only content-free aggregate counters are reported. No expert
IDs, scores, prompts or outputs are persisted or logged by this path.

This removes 48 per-token CPU maps and associated host route/header work, but
does not remove upstream GPU computation. Existing router-fence wall timings
include that computation. Physical operator/full-model acceptance and measured
performance are pending; CPU reference tolerances are not relaxed. Short
prefixes retain their existing disclosure and cannot claim full32 acceptance.
