# Public batched integer Q6 target head controller

This default-off internal controller selects the separate integer Q6 verifier
head for fixed public DASLab CPU13 warm and code/prose language benchmarks.
Source checks do not establish GPU acceptance or a throughput improvement.
It does not change installed inference, public APIs, target routing, reference
vectors, numerical tolerances, owner capacities, or physical admission.

## Exact registration

`KUNO_LAB_TARGET_HEAD=integer-public` is the only accepted selected value.
Absence preserves the original head. The selected controller requires Intel
MTP on its independent device/runtime, original full-Q8 MTP with fused sweeps,
immutable original frozen HOST sources, actual GPU router, partition exit,
direct fill, inline dispatch, fused Verify3, chunk I/O, request reuse, both
integer GU and integer DOWN, grouped PLE reads, and original bank fill.
CPU13 additionally requires its single original warm replay. Language uses
only its existing compiled code/prose fixtures and speculative execution.

The initial scope admits an absent or shared-Q8 MTP head, chronological QSA,
integer-GU stride four, grouped status folds, the previously scoped submission
backlog, scalar or batched MTP repair, and original three-row or genuine
four-row lookahead. Their existing individual restrictions still apply.
Three-streaming GDN remains available only in its existing three-row scope;
genuine four-row scope retains FourGdn/FourStreaming and its old exclusions.

The selected head rejects target-only, Nvidia MTP, Q2/other draft profiles,
English vocabulary, broadcast-Q8 head, IQ4 register decoder, profile-ranked or
preserved bank placement, private/workgroup tables, shared DOWN scales or GU
factors, old two-row GU/three-member arithmetic, packed HOST staging, original
four-row or stride DOWN, prepared experts, and live member reduction. Unknown,
empty, or duplicate selectors fail before model construction. Absence of this
new selector does not narrow any existing scope.

## Actual execution and completion

Original CPU13 cold replay, selected warm first-token prefill, and original
language prompt prefill all execute the original target head. Their completed
actual head selection and prepare/tile/member counters must be false/zero.
Only after those original boundaries and actual Source attachment, and before
the existing request begins, does the completed model wrapper activate the
immutable executor selection. No constructor reservation is execution credit.

Subsequent real target verification and real rejected-prefix recomputation
use the selected head for actual count one/two/three and, with genuine four
activation, count four. Original target/round/vector/greedy/cursor and scalar
or batched MTP repair authorities remain in their existing order. No token,
expert, or accepted prefix is forced. The original dense Verify3/Verify4
counters retain their generic-dispatch meaning; selected integer-head work
receives only its separate real counters.

Each completed head prepares once, performs exactly sixteen successful source
tile projections, and credits its actual member count only after every tile
succeeds. A small controller ledger counts each genuine verification chunk
and each actual recomputed accepted-prefix chunk, with their real member
counts. After request closing and the existing completed model proof, the
receipt requires selected/actual parity, prepares equal that ledger, tiles
equal sixteen times prepares, and members equal the actual verified plus
recomputed row counts. Selected normal completion requires positive work;
default/cold/prefill receipts require false/zero. Partial counters or a failed
projection cannot become a completed receipt. Overflow and counter mismatch
reject rather than changing a cap or attributing work to the generic head.

`target_integer_head_receipt` carries the completed selected flag and
prepare/tile/member counts; `initial_prefill_target_integer_head_receipt`
carries original false/zero evidence. The outer requested policy remains
separate. All fields are content-free, with no prompt, token, route, carry,
or tensor payload persistence.

## Validation and remaining acceptance

Focused checks must cover canonical/default parsing, missing required gates,
unknown/duplicate values and excluded scopes, unchanged existing selections,
three/four-row composition, default/prefill zero receipts, actual mixed tails
and recomputed prefixes, exact sixteen-tile joins, positive completion,
overflow, and false or partial credit. Existing original CPU13 full vectors,
carries, greedies and real repair remain the physical authority. Original
three-row and genuine four-row GPU gates and same-artifact normal timing are
root-owned and pending until explicitly recorded. No installed service or
frontend change is required.
