# Public target grouped status folds

This is a separate default-off native Rust laboratory policy. The eventual
protected selector is `KUNO_LAB_TARGET_STATUS_FOLDS=grouped-public`; the leaf does
not register a controller, Python guard, installed option or inference API.
Original weights, F32 equations/reductions, owners, privacy boundaries and caps
remain unchanged. No physical speed acceptance is implied by source tests.

`Config::reserve_public_grouped_status_folds()` grants construction permission
only. It requires the original DASLab target-row/checkpoint/public CPU13 or
language request construction, MAX8/member8/tile8, frozen sources and GPU router,
without hybrid, resident router, prepared experts or live member reduction.
There is no new allocation or reservation increase. The legacy process-global
`status_fold_batch::select` remains unchanged and cannot be used simultaneously
with this target permission or supply the new actual counters.

`ResidentModel::set_public_grouped_status_folds(executor, selected, cancel)`
requires the healthy original completed native boundary, real original frozen
source/router identity plus partition exit, direct Verify3/fused projection,
chunk/deferred/transient I/O, and no active request. CPU13 requires its genuine
one-shot warmreset and accepted position1 prompt; language requires its original
accepted prompt permit. Selection is immutable before first use and cannot be
disabled. All three actual workspaces are preflighted before any selection is
published. PLE and status selection may occur in either order. Original plain
GU or explicit GU integer/stride, four-row DOWN/stride, grouped PLE,
chronological QSA and Chunk/ThreeGdn may compose. Old single-member/projection
policies cannot be installed after selection.

Actual selected runs require count1..3, `AllRowsWithCarry`, and the full original
48-layer inventory. GR joins `[SN,SL,SM]` at the existing mix-ready boundary;
GDN joins all five original pointwise/recurrence statuses after output;
QSA joins only fixed statuses `[0,1,2,3,4,9,10,11]` after append. Every original
status initialization remains. GR combines and QSA token-specific variable-width
folds remain separate. Each grouped shader reads exactly the original active
count/first/stride/width spans and atomically ORs the same sticky fault bit2.
Inactive/gap/padding data never become evidence of successful active stores.
The original full owner/extent/alias and 4096-byte helper metadata guards remain.

The three workspaces count successful actual grouped launch calls independently
of the old global diagnostic counter. The coordinator snapshots their queued
counters before borrowing the real PLE/family permits. It then joins exact
97 GR,36 GDN,12 QSA actual deltas against the graph-derived layer roles after
both original full fault proofs and all-family preflight. The proposal remains
unpublished through every fallible commit, final bank proof, cancellation and
health check. Only then does the accepted completed receipt advance.

`completed_public_grouped_status_folds(executor)` returns `(selected, Completed)`
with public `chunks`, `gr_dispatches`, `gdn_dispatches`, `qsa_dispatches` counts.
Unselected must be false/allzero. Selected requires positive accepted chunks and
exact joined actual counts `chunks * [97,36,12]`; requested flags or enqueues
alone receive no credit. Full source/physical owner proofs and the healthy
completed native boundary are still required. Failed chunks terminally poison
the original sequence and cannot publish positive completion credit.

a reduction of422. The v161 code receipt has69 verification plus5 repair chunks,
so the same public workload would remove31,228 dispatches. This is a structural
count, not a runtime speed prediction; enqueue/submission/map timings overlap
and GPU work still executes. Original CPU13 full vectors/carries/greedy/actual
repair tolerances and full owning close/recovery gates remain mandatory before
normal paired timing.
