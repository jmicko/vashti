# Fixed public target grouped status controller

The separate default-off controller selector is
`KUNO_LAB_TARGET_STATUS_FOLDS=grouped-public`. It registers the immutable
model-local policy documented in
[grouped status folds](kuno-native-public-grouped-status-folds.md).
Absence retains the original status-fold path. Empty, malformed, duplicate or
incomplete choices reject before model allocation. This is an internal fixed
public lab candidate; installed inference and the ordinary API are unchanged.

Both CPU13 and code/prose200 controllers require the original frozen host
sources, actual GPU router, inactive partition exit, direct fill, inline
execution, Verify3-fused, chunk I/O and one request scope. CPU13 additionally
requires the original single warm replay and diagnostic bank placement; cold
replay remains unselected. Language accepts the original independently guarded
Nvidia or Intel draft placement, or actual target-only execution. No MTP profile
or sweep dependency is fabricated for target-only. Original Q8/Q2 restrictions,
Intel memory admission and borrowed Vulkan device-handle identity stay intact.

Grouped status, grouped PLE reads and DOWN stride-four scheduling are independent
choices and may be selected together or separately. Integer/stride GU, original
four-row DOWN, chronological QSA, shared Q8 head and bounded ThreeGdn retain their
independent gates. English shortlist, private/workgroup tables, shared DOWN
scales, shared GU factors, two-row GU, packed staging, three-member arithmetic,
preserved bank placement, prepared experts and live member reduction reject in
this initial scope. No GPU/host allowance, owning buffer, model shape, reference
or tolerance changes are granted by this selector.

`Config::reserve_public_grouped_status_folds()` runs before target construction
and permits the later immutable selection without selecting execution. The
controller queries `completed_public_grouped_status_folds()` after original
accepted prefill and requires false selection with zero chunks and all three
zero dispatch counts. Cold CPU13 and real language prompt prefill therefore keep
the original path. After consumed warm reset plus the original accepted first
CPU13 token, or accepted real language prompt/source attachment, it calls
`set_public_grouped_status_folds(executor, true, cancel)` before request I/O.
The parent permits composition with PLE selection in either order; controllers
currently select PLE first. An active policy cannot be disabled.

Completed receipts use the actual model-local `status_fold_batch::Completed`
returned only after the original completed boundary, full all-family commit and
late health proof. Global status flags and requested/enqueued work earn no
credit. The controller validates selection parity and an exact join:

- `completed_chunks = verification_chunks + actual_repair_chunks`;
- `gr_dispatches = completed_chunks * 97`;
- `gdn_dispatches = completed_chunks * 36`;
- `qsa_dispatches = completed_chunks * 12`.

Warm CPU13 uses actual returned verification rounds and counted repair packets.
Language uses its actual completed round and repair counters. Target-only has
one actual count1 target chunk per timed continuation and no draft/repair; a
full 200-output run has 199 such chunks after its initial accepted prompt output.
Initial prefill is excluded from these selected counts. Default/cold receipts
require zero in every completed field. Selected zero execution, overflow,
missing/surplus dispatches, selection mismatch or repair counts exceeding
verification rounds reject. These scalar receipts retain no prompts, outputs,
token IDs, vectors, routes or private user content.

The outer receipt names the requested policy in `target_status_folds` and
`target_grouped_status_folds_requested`. Each record/pass separately reports
actual `target_grouped_status_folds` plus `target_grouped_status_folds_receipt`
with `selected`, `completed_chunks` and the three `*_dispatches` fields.
`initial_prefill_target_grouped_status_folds` and its corresponding
`initial_prefill_target_grouped_status_folds_receipt` independently prove the
original false/zero prefill boundary.

`protected-lab-exec.py` accepts the same canonical selector and original scopes
before choosing the exact existing public cgroup cap. It rejects escape to other
commands, devices, generic caps or unknown private inputs. Input environment,
48 GiB CPU13 cap, 48 GiB plus 196 MiB language cap, swap/core protections and
ordinary defaults remain unchanged.

Source coverage checks canonical/default registration, every original
prerequisite, independent PLE/DOWN composition, original Intel/Nvidia and
actual target-only scope, exact completed family counts, overflow and false
credit. GPU numerical acceptance, full lifecycle recovery and same-artifact
normal timing are separate root-owned gates; source checks alone establish no
performance gain. Validation on the `66bdd0f` base plus parent `b9ebef5` passes all 37 language
controller, 30 CPU13 controller and 23 target-build helper tests (90 total),
including the new status scope and exact receipt coverage. All 33 protected
launcher tests pass, including six new status admission tests. Strict
direct-device all-target Clippy with `-j2` and warnings denied, formatting and
diff checks pass. These source checks do not establish physical acceptance or
performance. Root retains the numerical, owning close, recovery and normal
same-artifact timing gates.
