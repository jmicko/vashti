# Public frozen GU stride-four controller

The fixed public warm CPU13 and compiled code/prose200 lab controllers accept
`KUNO_LAB_FROZEN_GU_SCHEDULE=four-public` only alongside the already bounded
`KUNO_LAB_FROZEN_GU_MATH=integer-public` scope. Missing scheduling selection
retains the previous leaf. Empty, noncanonical, duplicate and integer-absent
selections reject before target allocation. Existing original math wrappers
continue to select false, and ordinary inference has no new selector.

Selected sources use the immutable
`attach_public_host_sources_with_gu_schedule` entry point from the
[parent contract](kuno-native-public-frozen-gu-stride-four-parent.md). The
controller records requested scheduling separately from actual completed
`native_frozen_source_gu_stride_four` selection. It accepts actual stride
dispatches only when they equal positive whole-layer integer dispatches:
five GU source partitions per preparation, 240 calls per completed all-layer
batch. Unselected sources require zero stride dispatch credit. Existing
integer preparation, full-owner audit, source routing and close checks remain
mandatory. This selector adds no target owners or budget increments.

The warm replay's first count1 token after reset uses selected scheduling and
must complete exactly the existing 48 integer preparations, 240 integer
dispatches and 48 owner audits, plus 240 selected stride dispatches. Its
original CPU13 position0 reference is unchanged. Original cold CPU13 and
compiled language prompt prefill continue to use their original path.

Receipts add `frozen_gu_stride_four_requested` outside each record,
`frozen_gu_stride_four` and `frozen_gu_stride_four_counters.gu_dispatches`
within it, and the actual `frozen_source_routes.gu_stride_four_dispatches`.
Warm records additionally include actual
`initial_prefill_frozen_gu_stride_four` and its dispatch receipt. No content,
individual routes, tokens or vectors are persisted by these additions.

Parser and receipt unit tests cover default/off selection, canonical opt-in,
the integer dependency, duplicates, false actual identity and missing/partial
dispatches. Physical reference, real language repair and matched scheduling
timings remain root-owned acceptance gates; controller unit checks alone do
not establish GPU correctness or throughput.
