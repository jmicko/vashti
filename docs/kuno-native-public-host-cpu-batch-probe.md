# Original HOST CPU batch operator comparison

## Scope and status

This specifies the first physical comparison for the borrowed CPU expert leaf.
It is an operator gate, not connected hybrid model inference or a tokens/second
claim. Source implementation and physical acceptance are separate receipts.
The approved first scope is one fixed public DASLab layer, one to three members,
original F32 CPU arithmetic and the unchanged frozen HOST GPU projection kernels.
No CPU/GPU rank-merge kernel, router substitution, alternate reference, ordinary
API, installed selection or cancellation policy is introduced.

The dedicated compiled-public entry is `intel public-host-cpu-batch-probe`.
It accepts only `KUNO_LAB_HOST_CPU_BATCH_PUBLIC_ONLY=1`, matching
`KUNO_LAB_DEVICE_DISPATCH=inline` in the direct-device build,
canonical `KUNO_LAB_STATIC_CACHE_BYTES=8589934592`, `KUNO_TEST_Q3_DIR`,
`KUNO_PUBLIC_TARGET_CARRY13_REFERENCE`, and
`KUNO_PUBLIC_RECEIPT`. These are the six allowed keys. Missing, duplicate,
noncanonical static-cache and inherited policy keys reject
before device/model construction. There is no MTP sidecar or draft device.
The existing original target construction uses the8GiB static cache,
144slots/layer and31GiB complete target capacity plan, including its shared
128MiB runtime I/O ceiling. Separate operator owners fit under4MiB. Root's
protected runner admits that complete plan against fresh physical Intel memory
with the unchanged512MiB driver margin before entering this mode. The original
public-target request runtime is configured before construction, with its
unchanged128MiB ceiling and separate4MiB HOST binding metadata reservation.
Threaded builds reject this fixed direct request-I/O gate.

Actual source preparation follows all13 original cold count1 rows, with full
logits/hidden vectors, greedy reference and completed cursor checked each time.
After cold token0, the existing actual public request scope begins; at completed
cold cursor13 it ends with its full original I/O audit before source preparation.
It retains the existing CPU13 diagnostic bank placement, prepares at cursor13,
performs the original accepted warm reset, attaches the real full mirror and
activates the original frozen GPU router. Real warm token0 is checked against
the same full reference before any CPU borrow. The existing Closed permission
allows that original token0 after the audited warm reset. The operator does not
open a second model request scope; its receipt records that scope as inactive,
and original model/runtime ownership audits still close every owner. Fixed
content-free phase markers identify configuration, constructor, cold13,
attachment, warm-token and operator-completion boundaries. The model wrapper delegates
only after its existing complete native projection boundary, retaining the
shared actual model workspace/executor and exclusive attachment borrow.

The original full CPU13 vectors, tolerance, greedy IDs, real speculative repair,
all-family fault and ownership closure remain authoritative and unchanged. A
later connected CPU/GPU split must pass them separately. Operator partials do
not establish that acceptance.

## Source and mapping authority

The gate borrows the existing actual attached public HOST mirror. It must not
materialize a second model mirror, copy packed expert payloads, add a CPU-borrow
model-file mapping, reopen source paths, or issue weight reads while comparing
operators. Initial original target loading/source preparation retains its
existing mapped-weight and payload-read path before the operator interval.
The full mirror remains 432 original allocations with
36,147,609,600 logical public RAM bytes and its existing physical envelope.
Existing actual loaded resident banks and their complete frozen512 maps remain
unchanged.

The private adapter is owned by `public_host_expert_mirror` and
`public_host_expert_attachment`, not the runtime interoperability crate. Mirror
owns the real Vulkan memory; Sources holds GPU resource pins and metadata, not
the physical RAM lifetime. CPU views therefore borrow Attachment, with no raw
pointer or clonable bare GPU page handle escaping that borrow.

Initial one-layer CPU mapping is limited to the nine existing role/page
allocations for that layer. Each map starts at zero and covers the actual
checked Vulkan backing extent, at most128MiB. Only immutable exact expert
subspans within the logical page are exposed. Allocation padding is never an
expert span. This maps the already-owned RAM, not a file or a second physical
payload. CPU/GPU consumers are both read-only. Their source lifetime ends only
after CPU worker joins and GPU completion; mutable zero/free remains after the
original exact432 detach receipts and queue join.

Original initialization writes are already flushed before GPU publication.
There are no GPU writes to these public weights, so operator execution needs no
per-call invalidation. Noncoherent cache operations retain offset0/WHOLE_SIZE
alignment handling and occur only at original initialization or exclusive
post-consumer zero/close. The new immutable map interface must not expose the
old mutable-map/cache/zero methods. Actual HOST_CACHED/HOST_COHERENT placement is
recorded, not guessed from allocation preference.

CPU expert IDs and each role's page, destination offset and full packed length
come from the attached Plan's actual address/range proof. The adapter checks
HOST tier, Plan identity, graph/model binding, frozen bank generation, registered
full resource binding and checked logical bounds. The CPU leaf then checks the
same original PackedExperts geometry identity for all borrowed views. Arbitrary
caller bytes, shape, source digest or original expert number alone cannot grant
this authority.

## Fixed cases and GPU comparison

The first cases use deterministic synthetic public inputs and public fixture
packets whose selected experts belong to the actual attached HOST complement.
They exercise real original model weights, not captured private routing. They
must be labelled synthetic operator inputs; they do not claim the original model
router chose those experts or that the vectors are actual hidden states.

Numeric cases cover counts1,2,3, sparse original ranks, all ten HOST ranks,
repeated expert use across members at different original ranks, and exact
inactive member/rank zeros in CPU BatchPartials. Expert/rank selection remains
unchanged between CPU and GPU controls. Probabilities are retained but are not
multiplied into the unweighted partials.

The GPU control invokes existing `grouped_gate_up_frozen` and
`grouped_down_frozen` on only the authenticated three HOST partitions with
virtual first slots144/288/432 and counts144/144/80. The same original geometry,
packed dtypes, original64 reduction, checked full private owners and actual
packet mapping apply. It does not invoke the complete five-shard Sources launch
and mislabel it HOST-only. It adds no arithmetic kernel or mutable source policy.
Each successful comparison verifies all selected unweighted partials, exact
inactive/tail rules, finite status, owning fault, unchanged sources and joined
GPU completion. The existing original partial bounds are absolute1e-4 and
relative3e-4; no tolerance is widened. Full-model bounds remain unchanged.

This initial control uses original F32 HOST GU/DOWN arithmetic. The selected
normal benchmark uses integer GU/DOWN arithmetic. A CPU win here establishes
neither a win against the best integer GPU path nor a whole-model speed gain.
The receipt records the control arithmetic and that the integer control was
not compared. Extending that comparison is a separate gate.

The dual source adapter must provide an opaque bounded dispatch/callback tied
to its live attachment borrow. A public accessor returning independently
clonable Handles is not acceptable. Private input/output owner identity, stream,
physical extents, nonaliasing, count and source span proof precede unchecked
kernel launch. The existing typed attachment/Plan remains source authority;
the gate cannot reconstruct or fabricate a RegisteredPage.

## Completed timing boundary and capacities

Numeric acceptance precedes timing. Timed cases use equal HOST subsets of
one, three, five and ten original ranks per member at counts1,2,3, including
expert reuse across all three members. Five HOST ranks is a representative
operator point for the currently observed approximately45percent HOST share;
it is not a prediction of future model routing. Every packet retains ten
original ranks/member: remaining ranks refer to actual resident experts, and
both partial-only arms skip their resident work identically. The missing
resident partials are never represented as a completed full layer. Paired
completed intervals compare equal selected HOST work. Source construction,
mapping setup, pipeline preparation and ordinary model prefill are reported
separately, not hidden within one arm.

The CPU arm starts from already resident owning GPU input and packet owners.
Its measured interval includes actual input/packet handoff to guarded host
owners, borrowed CPU batch execution and all worker joins, complete returned
partial encoding/upload into a separate owning GPU page, GPU finite/owner
checks and queue completion. At H2560 the leaf's complete three-member/ten-rank
logical output is307200bytes; inactive slots remain bitwise+0. The current
private upload controller requires an owned byte vector. After CPU workers have
joined and their input/activation/scratch owners have been erased and released,
the gate permits one bounded524288byte full-owner encoding copy alongside the
retained307200byte CPU result. The encoded owner's217088byte tail is exact zero;
the combined output phase is831488bytes before retained headers. Actual
capacities and retained caller headers remain
under the unchanged1MiB phased host cap. Encoding and upload cost are included
in the completed CPU interval and copied byte counts are reported. No unsafe
float-vector allocator reinterpretation is allowed. There is no
zero-cost host-input shortcut or fabricated GPU completion.

The original full input owner is131072bytes and the MAP/PROB owners are32768
bytes each. The CPU arm reads and validates the full packet owners sequentially,
releasing them before CPU computation. An existing GPU copy copies the first
three actual member inputs into a separate full32768byte handoff owner; that
copy and read are timed. Typed readback views require explicit four-byte
alignment, complete word extent and little-endian checks. No unaligned cast or
extra uncharged input-vector copy is permitted. The full original MAX8 input,
all eight partial rows, remaining full-owner partial/activation padding,
untouched output owner, readiness/status tails and uploaded CPU owner are
checked during separate untimed numeric acceptance in both arms.

The operator leaves the model's public request scope closed. That does not
disable private I/O: the existing configured runtime remains active, and every
readback/upload/INFO owner stays charged until its original sanitizer runs.
One pair performs3,997,696bytes of full-owner readback, including numeric and
owning-tail checks. The180pairs would retain719,585,280bytes of readbacks alone
without a checkpoint, exceeding the unchanged128MiB runtime cap. Dropping the
returned Bytes releases its lease but does not erase/release its GPU owner.

After each complete pair's numeric audit returns and every readback Bytes lease
has dropped, the gate uses the existing `sanitize_transient_io_audited` on the
same configured stream. This reclaims only original bounded transient I/O;
actual main/private result owners and attached public weight pages stay retained.
It adds no request permission, pool policy, capacity or owner. The receipt
records actual completed checkpoint counts, inspected bytes/buffers and time.
These full I/O cleanup checkpoints are outside both operator-arm timings and
reported separately. Such timings describe the completed operators, not a
whole-model throughput or total180-pair runtime. Fixed numeric case/pair phase
markers identify GPU, CPU, numeric-audit and checkpoint failure boundaries.

The source correction for the v171 setup failure passes five focused operator
tests, strict direct-device all-target Clippy with warnings denied, formatting
and diff checks. Its layout regression computes the complete per-pair readback
extent from the actual original padded BufferLayout values. Physical numeric,
timing and complete recovery acceptance of this correction remain pending.

The GPU arm starts with the same resident input and packet and measures the
original HOST GU/DOWN projections, finite/owner checks and queue completion.
Validation readback must either be inside both completed intervals or be
reported consistently as separate untimed acceptance. CPU-kernel-only and
upload-only subintervals may be reported, but are not the complete comparison.

Repeated work from one layer and small HOST subsets may fit the processor's
64MiB L3 and report unusually warm-cache CPU performance. This is an optimistic
operator measurement, not a prediction for48-layer model execution. Do not add
cache-flush infrastructure or large artificial scratch to this first gate;
later actual model timing decides its value.

Before allocation, charge all caller-owned private input/packet copies,
selection headers, leaf request/output reservation, worker scratch, encoding
buffers and actual capacities together. Subtract live caller-owned bytes from
the leaf's existing1MiB hard limit before executing it. If a worker count cannot
fit, reject that explicit case or choose a documented smaller fixed count;
never widen the cap. Release phase-local input/scratch owners before encoding
when necessary, without dropping source lifetime or returned output early.
The first worker points are explicit fixed physical-core sets of8,12,15 when
admitted. The bounded encoding phase above uses the existing owned transient
upload controller rather than adding a vendor upload API. Full weight bytes
are never duplicated.

Charge every additional GPU owner, runtime upload/read capacity and bounded
map/header allocation explicitly. Existing MAIN/private/runtime caps, HOST
metadata caps and physical Intel driver margin remain unchanged. This gate
cannot assume combined target+MTP headroom permits new private owners. It must
run under a clean explicitly admitted operator placement and publish exact
additional owner counts/bytes and full closing extents. No new public model
payload charge or duplicate RAM residency is credited.

## Later connected split

Existing Packet::from_plan retains original member/rank IDs and probabilities.
The later parent must classify each of those actual original ranks through the
same frozen source mapping, keep CPU HOST subsets sparse at original ranks and
compute resident ranks on GPU. No wrong expert substitution or omission of a
zero-probability rank is allowed.

The existing count1 hybrid map/merge deliberately requires count1 and old CPU
Partials. It does not authenticate count2/3 BatchPartials. Connecting those
counts needs a separately proved bounded original-rank merge and actual CPU
completion/source proof; this operator gate does not add it. Full model
timing and original CPU13 acceptance follow that later connection.

## Required receipts and limitations

Record only content-free aggregate source/owner/capacity/count and completed
timing fields: actual layer/count coverage, maps, unchanged full mirror totals,
zero additional packed-weight reads/copies, original GPU dispatches, CPU joined
calls, inspected full extents, numeric maxima, actual finite/fault results,
private erasure and original exact detached/backing recovery. Do not persist
expert IDs, original ranks, inputs, probabilities, partial vectors or prompts.

Source tests should cover malformed selectors, missing/wrong attachment/source
identity, stale generations, resident/expert/range rejection, duplicate maps,
full span/padding proof, private budget rejection, sparse exact-zero output,
default-unused behavior and failure/unwind joins. Passing them does not
establish physical speed, same-allocation execution, full model correctness,
or installed service stability.
