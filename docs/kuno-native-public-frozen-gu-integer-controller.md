# Compiled-public frozen integer GU controller

Internal native Rust laboratory candidate, 2026-10-11. This registration does
not change ordinary inference, APIs, catalog entries, installed services or
Vashti. The GU-only two-residual-Q8 arithmetic differs from the original F32
implementation; physical acceptance must use the unchanged original CPU13
reference, complete carries and greedy decisions, and original repair checks.
Source checks alone do not establish device correctness or throughput.
Noncandidate controller attachments continue through the original-math wrapper;
only selected candidates call the new immutable GU math attachment.

## Fixed selection and construction

`KUNO_LAB_FROZEN_GU_MATH=integer-public` is admitted only by the existing
compiled-public CPU13 warm-replay and first-code/warm-prose 200 controllers.
Absence preserves original arithmetic; empty, noncanonical, duplicate and
inherited experiments are rejected before device construction. Selection
requires all original frozen-HOST sources, actual frozen GPU router,
inactive-partition exit, direct-device inline dispatch, direct expert fills,
Verify3-fused, chunk I/O, request I/O reuse, fused MTP sweeps and the complete
self-contained Q8 draft. The first candidate rejects packed HOST staging,
private/workgroup tables, shared DOWN scales, GU factors, paired GU,
three-member MoE, preserved routed-bank placement, prepared experts, live-member
reduction, Q2 draft, broadcast
Q8 head and English shortlist. These are independent arithmetic or allocation
experiments that need separate acceptance before composition.

Original plain/four-row DOWN and plain/shared-scale Q8 head are allowed. The
separately bounded three-token streaming GDN may compose; its own actual
completion receipt remains mandatory. The original chronological GPU QSA
selector is allowed and retains its independent 49,152-byte runtime/INFO and
4,096-byte HOST increments. It adds no MAIN owners, so its inclusion does not
alter the candidate's exact complete MAIN receipt.

Before target allocation, the controllers set
`executor.target_frozen_gu_integer_reserved` and call
`Config::reserve_public_frozen_gu_integer()` after independently reserving
target rows, request scope and frozen source/router authority. Construction
precharges the one complete 64 KiB MAIN page, 65,536 HOST bytes, 196,608 INFO bytes
and 462,848 runtime bytes. The full owning target plan is 1,381 MAIN owners and
828,932,096 bytes. Existing candidate-independent owner proofs remain intact.
The complete original Q8 draft retains 5,011,668,992 public bytes, 42 private
owners/11,698,176 bytes and zero MAIN after closing.

## Original prefill and actual candidate dispatch

The cold CPU13 pass and real language-prompt prefill remain original arithmetic:
the extra zeroed private owner is present, but the immutable integer source set
has not been attached. The warm CPU13 controller completes its original cold
reference replay, performs the complete private reset, then attaches with
`attach_public_host_sources_with_gu_math(..., three_members, gu_integer,
cancel)` and activates the actual frozen GPU router at cursor 0. Its initial
count 1 token therefore uses integer GU and must pass the unchanged original
position 0 vectors, carries and greedy decision. Before continuation timing,
`initial_prefill_frozen_gu_integer` and
`initial_prefill_frozen_gu_integer_counters` additionally require actual true and
exactly 48 preparations/240 GU launches/48 full audits for that first count 1
batch; the cold first token requires actual false and zero counts. It has no original-math
fallback. Language attachment occurs only after the complete real prompt
prefill, before ordinary continuation generation and request I/O reuse.

The controllers obtain the completed source-specific mode from
`native_frozen_source_gu_integer(&executor)`. The actual immutable source flag,
precharged workspace and healthy all-family completion must agree. The parent
creates evidence only after one preparation, five original-source GU launches
and the complete scratch-owner audit join the original route/output/family
proof. Requested flags and generic DOWN dispatches cannot supply these counts.

## Content-free receipt contract

Each completed pass/normal record includes:

- `frozen_gu_integer`: actual completed source mode, not the requested flag.
- `frozen_gu_integer_counters`: `preparations`, `gu_dispatches`, and
  `full_owner_audits`, validated as positive whole 48-layer batches with exactly
  five GU launches and one audit per preparation when selected.
- `frozen_source_routes`: the same source-specific counters under
  `gu_integer_preparations`, `gu_integer_dispatches`, and `gu_integer_audits`,
  alongside existing aggregate route/source/staging counts.

The cold CPU13 record reports actual false and zero candidate counts. The warm
receipt includes its initial count 1 dispatch and every accepted verification
and actual repair, even though initial prefill lies outside continuation timing.
All unselected records require all candidate counts to be zero. Arithmetic
overflow, missing/partial evidence, mode mismatches and malformed counters
reject the receipt. No token IDs, selected expert IDs, outputs, logits, prompts
or private user content are written.

The outer record reports `frozen_gu_integer_requested` plus independent
`frozen_gu_integer_extra_main_bytes`, `frozen_gu_integer_extra_host_bytes`,
`frozen_gu_integer_extra_info_bytes`, and
`frozen_gu_integer_extra_runtime_bytes`. Requested metadata is never treated as
actual dispatch acceptance. Both warm-reset and final target closure require
exact 1,381/828,932,096 candidate MAIN totals in addition to original complete
owning erasure and immutable-source detach/free proofs. Source closure is
attempted before rejecting a mismatched closing total. Existing noncandidate
close policies are unchanged.
